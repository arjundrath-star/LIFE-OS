# WP5: Reminders, notifications, memo, Hermes capture (Codex for code, Fable for Hermes)

Goal: the tab pushes to Arjun's phone and inbox on its own, and Arjun can push people into it from iMessage. Branch from feature/stern-tab after WP3 and WP4 are merged.

## Codex part
- lib/stern/notify.ts: send({channel: imessage|email|both, subject, body, urgent}) with STERN_NOTIFY_DRY_RUN=1 default outside production (records to stern_reminders.error "dry-run" and returns). iMessage: runs the Hermes alias from kv "stern.hermes_alias" (default "stern", fallback "personal-trainer") as `<alias> send -t "<kv stern.imessage_target>" "<text>"` via execFile with argv (no shell), 20 s timeout. Email: python MIME + gws (reuse the exact mechanism in scripts/stern-build/email.sh, factored into lib/stern/email-send.ts with argv only), from arjun@kladeai.com to kv "stern.memo_email" (default arjundrath@gmail.com), subject prefixed "[Stern]". Both log to stern_reminders delivery fields.
- lib/stern/reminders.ts: evaluateRules(now) inserts due stern_reminders rows idempotently (UNIQUE guard): deadline_t7, deadline_t3, deadline_t1, deadline_day (08:00) for every open program deadline and interview; reply_owed (coffee chat reply_needs_me=1 older than 30 min, then every 4 h, urgent); thank_you_due (chat done more than 20 h ago without thank_you_sent, urgent at 22 h); no_reply_3d (requested 3 days ago, no reply: nudge to send the follow-up draft); interview_eve (18:00 the day before, includes dress code and location); task_due (08:00 for tasks due today); suggestions_pending (once daily when pending > 0). dispatchDue(now): sends pending rows with fire_at <= now, honoring quiet hours 23:00 to 07:00 America/New_York for non-urgent rows (snoozed to 07:00), marks sent or failed with the error.
- scripts/stern-memo.ts and lib/stern/memo.ts: buildMemo(date) composes the 08:00 memo from the stern snapshot (today's classes and coffee chats and interviews from calendar and course meetings, deadlines within 7 days, reply owed, thank-yous due, tasks due, suggestions pending, auto-applied yesterday count) plus the business and career snapshots already exposed by /api/vending, /api/pokemon-ops, /api/career (read through their lib functions, not HTTP). Email gets the full memo (plain text, sections, no markdown tables). iMessage gets at most 8 lines of the urgent items and ends with "Full memo in email." Optional polish through lib/stern/llm.ts with a {imessage, email} schema; deterministic template must work when STERN_LLM_MODE=off. Idempotent per day via kv stern.memo_last_date. Scheduler: tickSternReminders every 60 s (evaluate then dispatch) and tickSternMemo checking every minute for 08:00 local. npm run stern:memo -- --dry-run prints both versions.
- API additions in app/api/stern/automation/route.ts: GET reminders live tail; POST reminder.snooze, reminder.send_test, memo.send_now, settings.update (kv keys above). UI for these lands in WP6; expose the data now.
- Tests tests/stern-reminders.test.ts: rule idempotency, quiet hours, urgent bypass, memo builder with fixture data, dry-run never spawns a process (assert via an injected runner).
